Tutorial: Structured Regex (rx:) FindHelper

A human-readable, S-expression based regular expression alternative inspired by Emacs Lisp rx.

1. Why rx: ?

Traditional regular expressions in search boxes suffer from dense punctuation, escaping hassles, and lookahead fragility:

# Raw ECMAScript Regex: cryptic and escaping-heavy
re:^(?!.*[\\/](?:build|node_modules)[\\/]).*[\\/]src[\\/].*test_[a-zA-Z0-9]+\.(?:cpp|h)$

With rx:, the same logic is written using self-documenting S-expressions where bare words require no quotes and directory slashes work seamlessly across Windows and POSIX:

# Structured rx: clean, readable, self-documenting
rx:(path
     (exclude-dir build node_modules)
     (dir src)
     (name (seq test_ (+ alnum)))
     (ext cpp h))
Core Principles of rx:
  • No mandatory quotes: Words like cpp, src, test_ are written plainly. Use double quotes "..." only when tokens contain spaces (e.g., (dir "Program Files")).
  • Auto-escaping: Dots, brackets, pluses, and stars are treated literally in names. (seq CMakeLists.txt) matches literal dots.
  • Unanchored by default: Matches anywhere in target strings, unless anchored with bos (beginning of string) or eos (end of string).
  • Zero hot-path overhead: Lowered to optimized ECMAScript regex with SIMD Boyer-Moore literal prefilters before parallel search workers start.

2. Interactive Immediate-Mode UI Guidance

As you type into FindHelper's Path or Name input fields, real-time styling guides your syntax:

Border Indicator State Behavior & Diagnostics
Cyan Border Valid rx: Query compiles cleanly. Hovering displays the emitted regex and harvested SIMD literal prefilter.
Amber Border Incomplete Unclosed parentheses while actively typing: [rx: incomplete] missing ')': unclosed '('.
Red Border Syntax Error Detailed error message with "did you mean" suggestion (e.g. unknown operator 'dire' (did you mean 'dir'?)).

3. Language Reference

A. Sequences & Alternatives

Operator Example Description
seq, :, and (seq hello world) Concatenates expressions in order (emits helloworld).
or, | (or cpp h hpp) Matches any one alternative (emits (?:cpp|h|hpp)).

B. Quantifiers & Repetitions

Operator Example Description
*, zero-or-more (* digit) Zero or more repetitions (greedy).
+, one-or-more (+ alpha) One or more repetitions (greedy).
?, opt (? "_backup") Optional: zero or one occurrence.
repeat (repeat 4 digit)
(repeat 2 4 hex)		 Exact count {N} or bounded range {MIN,MAX}.

C. Character Classes & Sets

Construct Example Description
any (any "a-z" "0-9" "_") Custom character class (emits [a-z0-9_]).
not (not digit)
(not (any "aeiou"))		 Character negation (emits [^0-9]).
Named Classes & Wildcards digit, alpha, alnum, space, blank, word, xdigit, any-char (or any, anything) Standard ASCII character classes and wildcards.
Anchors bos, eos, bow, eow, word-boundary Start/end of string (^, $) and word boundaries (\b).

D. Path Extensions (V1)

Operator Example Description
path (path ...) Root wrapper assembling path-level constraints.
dir (dir src)
(dir src include)		 Matches a folder segment anywhere in path ancestors. Multiple args act as alternatives.
exclude-dir, not-dir (exclude-dir build .git) Anchored negative lookahead preventing results from specified folder names.
name (name (seq test_ (* alnum))) Constrains the filename stem.
ext (ext cpp h) Matches file extensions at end of path (leading dots automatically stripped).

4. Hands-on Practice Recipes

Recipe 1: C++ Headers in Include

Find all .h/.hpp files located under an include directory:

rx:(path (dir include) (ext h hpp))

Recipe 2: Ignore Build Artifacts

Search config files while pruning build noise:

rx:(path
     (exclude-dir build target node_modules)
     (name (seq config (* any-char))))

Recipe 3: Numbered Server Logs

Find server logs ending with a 4-digit year:

rx:(seq "server_" (repeat 4 digit) ".log")

Recipe 4: Typo-Tolerance in Action

Type an unknown operator to verify immediate-mode suggestion:

rx:(dire src)
# Output: unknown operator 'dire' (did you mean 'dir'?)
